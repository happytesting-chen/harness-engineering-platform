The interlock

Four gates, fixed order. The first denial ends the call.

  1. 1a

    Protected paths

    8 built-in write targets, plus protected_paths. Matched on file identity, so ../, absolute forms, symlinks and case variants all collapse to the same file. Policy cannot switch this off.

  2. 1b

    Deny-list

    10 patterns from deny-list.json. Shell command strings only — a file write carries no command, which is why gate 1a exists.

  3. 2

    Phase gate

    The active phase in feature_list.json against mcp-allowlist.json. A tool nobody approved fails closed: not in allowlist.

  4. 3

    Egress

    Five tokens — curl wget nc ssh nmap — against egress_hosts. Bash only. Friction for shell commands, not network enforcement.

Phase state

    Sign-off unlocks the gated tool for real. Nothing verifies that a human did it — feature_list.json is not a protected path (SEC-PHASE-GAP-001).

    • Two functions, two shapes. These handlers return a
            string, so this site calls scan_text. An ingestion point that
            returns a record — a KB hit, a DB row, an email — calls screen_record,
            which also drops unexpected keys. The panel above demonstrates the record form.
      • 
          
    • It cannot be a hook. PostToolUse fires after the side
            effect and cannot block, and no event exists for a result entering context. In-process
            is the only place it fits.
      • 
          
    • The caller decides what suspicious means. Both functions report and
            neither blocks. Prepending a banner is the floor; routing to human review is the honest
            version.
      • 
          
    • What it buys. SEC-CONTENT-001 moves
            LIBRARY → OBSERVE, and needs a test proving an ingestion path calls it —
            tests/test_content_trust.py only proves the function is correct alone. If
            only scan_text gets wired, that matrix row's cited function has
            to change too: it currently names screen_record.

    What this viewer is not
    
    
      
      
    • Not the enforcement path. Production enforcement is
        .claude/settings.json PreToolUse hooks calling the same CLI. This is a
        window onto it.
      • 
      
    • It never runs your command. The text becomes JSON on another
        process's stdin. Nothing here executes it, in either enforcement mode.
      • 
      
    • It never touches your policy. The gate and deny-list are copied into
        a scratch tree; the SHA-256 above is proof they were copied unmodified.
      • 
      
    • Gate attribution is read back from the reason string the gate
        returned — it is not predicted in advance.
      • 
      
    • The ingestion panel is half real. The screening output is genuine —
        screen_record ran on that record. The code that would call it at ingestion
        time does not exist (SEC-CONTENT-001), so the right-hand lane is a
        proposal, labelled as one.
      • 
      
    • Only five tool names reach the gate in production.
        Bash Write Edit MultiEdit NotebookEdit. Everything else is unrouted
        (SEC-COVER-GAP-001), which the WebFetch preset demonstrates.
