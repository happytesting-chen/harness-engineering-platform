What happened behind it

  
One loop. Five boundaries. A mechanism on one of them.

  

    An agent turn crosses the same five boundaries every time. The red path is the
    attack you just ran: in at 4, through the model, out at 2 — where
    it stops.
  


  

  
  


  
    
    
  • 2 is the only enforcement point.
      A mechanism can refuse a request. It cannot refuse a belief.
    • 
    
  • 1, 4 and 5 are open, and each has a row
      in Security-kit/control-matrix.md saying so:
      SEC-PROMPT-GAP-001, SEC-RESULT-GAP-001,
      SEC-SEQUENCE-GAP-001. Documented as gaps, not as coverage.
    • 
    
  • So the design assumes 4 succeeds.
      The defence sits between the model's intent and the world, not inside the model.
    • 
  






  
Small print, because the demo is the argument

  
    
    
  • Beat 4 is measured. The exit code and the reason string come from
      governance/permission.py, byte-identical to the one in this
      repo, running in a scratch copy of the policy tree. Your policy files are
      never written to.
    • 
    
  • Beat 2 is scripted. No model was called. The template's own
      evaluations use a scripted model for the same reason: a defence you can
      only demonstrate with a cooperative model is not a defence.
    • 
    
  • Beat 1's screening is a library nobody calls yet.
      content_trust.py works — you just watched it — but no ingestion
      path in this template invokes it, and once wired it reports rather than
      blocks. SEC-CONTENT-001.
    • 
    
  • Nothing is executed. Not in harness mode, not with the harness
      removed. The proposed command is JSON on another process's stdin.
