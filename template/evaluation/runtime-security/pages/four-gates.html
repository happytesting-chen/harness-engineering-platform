In short

A library your agent calls, that decides what it is allowed to read and do.

It is not a proxy, a gateway or a hosted service — nothing leaves your infrastructure and no traffic is routed anywhere. It is Python that runs inside your own application, between your agent and its tools.

What you integrate
One entry point

Your agent calls the gate instead of calling tools directly. Every tool has to go through it — that routing is the integration, and the part a review checks.

What it needs
Standard library, one local model

No cloud dependency, no API key, no telemetry. A small classifier runs locally, pinned by cryptographic digest.

What you get
Refusals and evidence

Hostile input withheld, unsafe actions refused before they run, and a tamper-evident record of every decision.

The problem

An AI agent never acts. It asks — and today, nothing independent answers.

Everything an agent does begins as a request: send this email, run this command, read that file. Security is whoever answers that request. In most deployments the answer is: whatever the model emitted, happens.

That matters because an attacker doesn't need to breach the agent. They only need to get text in front of it — a poisoned document, a booby-trapped page, a planted database row. The agent reads it with the same trust it gives your own instructions.

Guidance inside the model — system prompts, skills, careful instructions — improves judgement but shares a channel with the attack. Whatever persuades the model also disables the instruction. Enforcement has to sit outside the model, where nothing in the conversation can argue with it.

The mechanism

Five positions in an agent's loop. Four now carry a control.

Each control exists twice — once as an IDE hook while your team builds, once as an in-process call inside the product you ship — reading one shared policy, so a rule change moves both at once.

Capability, plainly

What it does, and what it does not.

Does

  • Withholds hostile inputRules plus a pinned local classifier. Nothing enters context unless both clear it.
  • Refuses actions before they happenA denied call means the tool was never invoked — proven by counting calls, not reading messages.
  • Replaces poisoned tool outputPer call, including results a subagent returns.
  • Bounds a whole sessionPer-tool and total budgets, correct under concurrency.
  • Tracks where content came fromA turn touched by external content cannot reach a tool reserved for direct user requests.
  • Puts a human in the loop, safelyQuarantined text is reviewed on an inert surface; release is a single-use receipt bound to one exact digest.
  • Refuses to start when misconfiguredAn unsupported capability or an unverified classifier is a startup failure, not a warning.
  • Leaves tamper-evident evidenceHash-chained records; editing one breaks verification at that point.

Does not

  • Force your application to use itThe single most important limit. Nothing can make a codebase route its calls through the gate — that stays an architecture decision, verified by review.
  • Catch every paraphraseTwo measured misses, both attacks that impersonate ordinary workflow. The classifier was confidently wrong on both; the action gate is what stops them.
  • Bound the review queueFail-closed screening means false positives queue for a human. No cap ships; your deployment sets one.
  • Cover multi-agent systemsDelegation and inter-agent messaging are disabled, not secured.
  • Read binary documentsUTF-8 text only. PDFs and images are refused, not parsed.
  • Remember across sessionsNo persistent memory. Budgets bound one run.
  • Confine the operating systemThis is an application-layer control. Sandboxing is a separate concern.
How it is built

Five construction rules, each one enforced by a test.

Deterministic first, model second

Pattern rules run on every item in microseconds. The classifier is consulted only on what the rules left unresolved — and it can withhold content, never authorise an action. No model decides an enforcement verdict.

Every failure is a refusal

Classifier timeout, crash, malformed reply, low confidence, unreadable policy, oversized input — thirteen distinct failure shapes, all tested, all landing on withhold. There is no path from a broken component to an allow.

One owner per rule

Detection patterns live in exactly one file; every adapter imports them. Tests scan module source to prove no second copy exists — a duplicated rule is a rule that drifts.

Composition, never reimplementation

The session layer wraps the existing action gate rather than rebuilding it. Adding a control cannot weaken one that already works.

Side effects are the oracle

Tests assert calls == 0 after a denial — the tool genuinely never ran. A test that only inspects a return value passes whether the control worked or not.

Release status

Signed as deployable — under five conditions, with an expiry.

Deploy with rules

Not certified unconditionally, on purpose.

A stronger verdict was available and was not taken. Nothing in a library can force an application to route its tool calls through the gate, so that guarantee is carried by a condition on the deployment rather than a claim in the code.

  • C-1Every tool call reaches its function through the gate — confirmed by architecture review with a recorded walkthrough.
  • C-2Production mode with a verified classifier lock, evidenced by a captured startup report.
  • C-3A review-queue bound is stated, or unbounded load is accepted in writing with a named owner.
  • C-4An independent security review — not the authors — completes the checklist.
  • C-5The pinned artifacts do not change; continuous integration checks this every build.

The verdict expires on a fixed date, or the moment any pinned artifact changes. Evidence has a shelf life: every figure was measured against one tree, and a verdict that outlives its measurements is an assertion, not a finding.
